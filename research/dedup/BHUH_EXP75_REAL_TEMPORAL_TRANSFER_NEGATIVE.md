## Source representational scope (important)

Two separate real physical image sequences were acquired from the scikit-image standard data library, not generated by simulated sprite edits.

1. `data.protein_transport()`: fluorescence microscopy, original **uint8**, 15 timepoints × 2 channels. We use the **first eight actual timepoints**, original channel 0 and central 128×128 crop, preserving original geometry and frame order. [Upstream scikit-image fluorescence workflow](https://scikit-image.org/docs/stable/auto_examples/applications/plot_fluorescence_nuclear_envelope.html).
2. `data.nickel_solidification()`: synchrotron X-ray radiographs, original **uint16**, 11 temporal frames. We use the first eight frames, central 128×128 crop. [Upstream scikit-image solidification workflow](https://scikit-image.org/docs/stable/auto_examples/applications/plot_solidification_tracking.html).

**Fixed shared conversion** for both: map grayscale to uint8 by one global min/max across the eight original crop frames (no per-frame normalization), then duplicate grayscale into RGB channels. The encoded files preserve the *derived* 8-bit RGB samples exactly, not the original 16-bit measurements. The full original movie, selected original crop and derived frame source SHA256 and input dtype are preserved in each archive manifest; artificial 100-ms display timing is a reproducible playback convention, NOT original physical experiment timing. No color scene inference or real 16-bit archive claim.

## Frozen real temporal test

Do not alter Exp74's 16×16 exact SHA256 dictionary, 512 uint16 tile references, lossless WebP dictionary atlas method or standard baselines. Each source has 8 original temporal frames, 64 tiles per frame. Same seven actual decoded codecs per source, complete metadata and checksums counted:

- exact dictionary + zlib;
- exact dictionary + WebP lossless atlas;
- real native lossless animated WebP;
- APNG lossless;
- one full eight-frame WebP lossless atlas;
- one full eight-frame PNG lossless atlas;
- raw frame bytes + zlib.

Every one of the **14 complete serialised files** was decoded and matched byte-for-byte to all eight derived RGB frames. The GitHub audit reloads both original scientific source sets independently and compares all metadata and original/derived SHA256.

## Official confirmed results

| Real temporal sequence | Unique 16² RGB tiles across 8 frames | Duplicate references / 512 | Best BLKH dictionary (B) | Best lossless standard (B) | Custom vs standard |
|---|---:|---:|---:|---:|---:|
| protein_transport | **512** | **0** | 73,795 | **72,616 (whole WebP atlas)** | **+1.62% larger** |
| nickel_solidification | **512** | **0** | 75,798 | **73,231 (whole WebP atlas)** | **+3.50% larger** |

**Result:** `0/2` real temporal videos satisfy Exp75's predeclared dual-source criterion. Across these 2 sources, there was **not a single exact 16×16 RGB block repeat** after the published shared 8-bit conversion, even though the images are from the same original experiment and consecutive timepoints. That is why an exact content-addressed dictionary cannot amortize its index and unique tile-encoding cost in this particular real video case.

Contrast with Exp74, which yielded **15/15 wins in nonzero synthetic-edit scenarios** but specifically reused a small, fixed 64-tile donor pool across frames. The unique tile count never exceeded about 128 there, compared with 512 for genuine time-lapse microscopy; this difference explains the loss without altering the original favorable result.

**Scientific interpretation:** exact duplicates are powerful on static or locally edited sprite assets, GUI/diagram assets, repeated binary blocks, and certain screen content. However, real temporal image acquisition often has sensor noise, subtle motion, illumination shifts or changing features that destroy exact equality. A 0.0 RMS pixel error guarantee does not create reuse when source data lacks identical blocks.

## Nonclaims and next falsifiable hypothesis

This experiment does not compare codec performance on raw uint16 scientific sequences (current WebP-like RGB test format cannot do so without changing representation). It does not evaluate native lossless scientific JPEG2000/TIFF temporal delta compressors, AV1 lossless, FFV1 or modern motion-compensated screen codecs. There are only two independent time-series sources, not a statistically representative video benchmark.

**Decision:** Do NOT generalize Exp74's genuine specialized advantage to naturally changing video or scientific movie data. Preserve the strong specialized result for deterministic asset updates, but do not modify public demo, main branch or describe the project as a breakthrough in universal video compression.

A well-grounded next experiment is a **true lossless temporal predictor** on the **same actual real time series**: encode RGB frame 0, then bytewise modular temporal differences/XOR between consecutive frames plus entropy coding, decode every original derived uint8 pixel and compare against entire WebP/PNG atlas and native animations with matched complete metadata. Unlike exact block dictionaries, temporal prediction can exploit *nearly equal* frames. Still an established method and must not be called new. Predeclare the predictor settings prior to inspecting encoded results.
